# HOW TO WRITE A CASE STUDY
#
# 1. Copy one of the files in this folder, or just edit rakta.md, hackbios.md, yumemi.md, haven-her.md.
#    The file name must match the project: the title in lower case, spaces and "&" turned into "-".
#    (Rakta -> rakta.md, HackBIOS -> hackbios.md, Haven & Her -> haven-her.md)
# 2. Fill in the fields between the two "---" lines. Leave a field empty to hide it. Only write things that are true.
# 3. Write the story below the second "---" line, in plain markdown.
# 4. The project page goes live (and is linked from the home page) as soon as the story below the fields is not empty.
#
# FIELDS
#   summary:    one sentence, shown under the title and on the home page card
#   status:     e.g. Live, Prototype, Hackathon build
#   year:       e.g. 2026
#   role:       what YOU did
#   stack:      what it was built with
#   problem:    the problem it tackles, in a sentence or two
#   decisions:  the key decisions you made
#   live:       https:// link to the working site or demo
#   source:     https:// link to the code
#   tags:       comma separated, e.g. React, Python, Design
#
# MARKDOWN YOU CAN USE IN THE STORY
#   ## A heading        ### A smaller heading
#   **bold**   *italic*   `code`   [link text](https://example.com)
#   - a bullet list     1. a numbered list      > a quote      --- a divider line
#   ![what the picture shows](/projects/rakta-1.png)
#      (put images in public/projects/ and refer to them as /projects/<file name>)
